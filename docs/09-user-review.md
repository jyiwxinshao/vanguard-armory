# 用户端检查与修补

检查日期：2026-09-15。当前分支 `feat/user-polish`，基于已经提交的 Stage 5 订单系统。保留现有首页、搜索、详情与通知界面的工作区修改；本次不实现管理后台。

## 检查结论

按当前课程设计范围，用户端已具备注册登录、身份恢复、装备搜索筛选与详情、游客和服务器购物车、登录合并、确认下单、模拟支付、取消、订单历史及详情。主要交易流程已接通。

已核对认证/购物车/订单 Store、Axios 会话保护、路由、数据库订单事务及已有测试。未发现需要重构的主流程问题，补齐以下衔接：

- **下单恢复入口**：原来恢复操作只在确认页。若响应丢失后离开页面，服务器购物车可能已为空，用户无法从结算按钮重新进入。现在“我的订单”读取当前账号的本地下单记录，有记录时显示“恢复上次下单”。记录损坏不阻断订单历史；换账号立即清理内存提示，另一账号不显示原记录。
- **越界页码**：直接访问很大的订单页码、或状态变化后原页不再存在时，按真实总数自动跳到最后有效页，空列表回第一页。页面离开、账号切换或新查询发生后，旧查询不能再触发页码跳转。
- **筛选与分页一致性**：分页统计和翻页使用地址中已经提交的筛选条件；仅修改表单但尚未点击“查询”，不会提前改变当前列表的分页含义。
- **日期边界回归**：补充前端本地日期到 UTC 次日零点的断言，以及真实 MySQL 左闭右开边界测试。边界时刻的订单仅属于后一个区间。
- **文档同步**：移除订单未实现、旧确认路由、缺少提交编号等过时说明，补全创建/恢复接口及两种持久重试记录。

## 本轮浏览器验收

使用独立临时账号在本地页面实际执行：

- 游客从装备详情加购，购物车显示 1 件；刷新后仍保留。
- 错误密码停留在登录页；正确登录后自动合并，原游客条目数量仍为 1。
- 确认页显示 1 件；另一标签页将服务器购物车改为 2 件。提交旧确认单被拒绝，没有按过期数量成交。
- 离开确认页，打开 `/orders?page=999&page_size=10`，自动回到第 1 页并出现“恢复上次下单”。
- 从恢复入口返回，重新确认显示最新 2 件，成功创建待支付订单，金额 16 元。
- 点击取消并确认，页面显示已取消与取消时间；数据库核对该装备库存恢复为 200。
- 按“已取消 + 当天日期”组合查询得到本次订单，刷新后筛选条件与结果均保留。
- 退出后受保护订单页回到登录入口，另一购物车标签同步切为游客空车，未复制账号购物车。

临时账号、其合并记录及已取消的测试订单均已定向清理，已有用户及业务订单保留。未在本轮通过浏览器人为注入断网、数据库竞争或完成所有窄屏设备检查；这些不能用页面成功记录代替。模拟支付页面主流程记录保留在第五阶段，相关自动回归本轮全部重跑通过。

## 范围以外

管理端交付与 `paid → completed` 操作仍未实现；用户已能读取 completed 状态。真实支付、退款、超时自动取消、修改/找回密码、头像上传、评价和优惠券均未纳入当前已确认的用户端基础范围。本轮不自动扩展这些功能。未支付订单仍占用库存，需要用户支付或取消；管理功能和最终交付材料另行完成。
