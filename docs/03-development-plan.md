# 单人开发与验收计划

> 当前状态：工程基础和第二阶段认证功能已实现；后端与真实数据库认证测试已通过，浏览器点击流程尚未验证。最新测试状态见[第二阶段记录](05-stage-two.md)，其余业务模块仍待实现与验收。
> 面向一人完成课程项目；先完成当前设计确定的基础功能，再根据剩余时间选择扩展。任务书仅作参考，明显错误和无关内容直接忽略。

## 1. 范围和完成标准

- 技术栈：JavaScript ES Modules；Vue 3、Vite、Vue Router、Pinia、Axios、Element Plus；Express、MySQL、mysql2、JWT、bcrypt。
- 单仓库目录：`client/`、`server/`、`database/`、`docs/`；数据库保持用户、装备、购物车、购物车明细、订单、订单明细六表。
- 普通用户流程：注册/登录 → 浏览 → 加入购物车 → 登录合并 → 整车确认 → 下单 → 模拟支付 → 查看订单。
- 游客可浏览并使用本地购物车；登录合并成功后使用服务器购物车，下单必须登录。
- 价格和金额按整数分处理；基础版优惠金额 `discount=0`，页面展示总价、优惠和应付，支付成功后展示实付。
- 下单生成 `pending` 并扣库存；用户或管理员只能取消 `pending` 并返还库存；支付转为 `paid`，管理员完成交付后转为 `completed`。
- 管理员库存调整使用独立增减操作；普通装备编辑表单不覆盖库存。
- 基础完成不依赖真实支付、退款、自动超时取消、完整幂等系统、WebSocket、复杂视觉效果或其他加分项。
- 功能范围以已确认的项目设计为准；任务书中的影院等无关内容直接忽略，不列入待确认或验收事项。
- 当前保持已有页面视觉、文案和布局，仅添加认证所需入口与表单；UI 后期由用户自行调整，不将页面重设计加入本阶段。
- 定义完成：本方案确定的基础功能通过验收、阻断问题修复、初始化可重复执行、文档齐全、演示视频可完整复现业务闭环。

## 2. 工作量估算

以下为可调整的有效工作时间估算，不是承诺交付日期；没有截止日期时不排固定日历。学习、环境排障和返工会影响实际用时。

| 阶段 | 预计时间 | 交付结果 |
| --- | --- | --- |
| 基础环境与数据库 | 6–10 小时 | 可启动的前后端、六表、初始化数据 |
| 认证与权限 | 8–12 小时 | 注册登录、登录保持、角色和冻结校验 |
| 装备浏览 | 8–12 小时 | 完整列表和详情体验 |
| 购物车 | 10–16 小时 | 游客与登录购物车、合并、整车结算入口 |
| 订单 | 14–22 小时 | 创建、支付、取消、快照、历史查询 |
| 管理端 | 12–18 小时 | 装备、库存、用户、订单管理 |
| 验收与交付 | 12–20 小时 | 测试记录、文档、初始化复核、录屏 |
| 合计 | 70–110 小时 | 基础版课程项目 |

每阶段按“数据库/接口 → 页面 → 联调 → 验收”形成一个可用模块；不先写完全部后端再集中写前端。

## 3. 阶段任务与验收门槛

### 阶段一：基础环境与数据库

- [x] 建立四个目录、依赖、启动脚本、环境变量示例和忽略规则；连接参数放环境配置，不提交真实密码或密钥。
- [x] 创建六表、唯一索引和必要外键；用户名、邮箱、订单号、用户购物车及同车同装备的唯一性在数据库中约束。
- [x] 准备初始化及种子数据脚本，包含 16 件装备、1 个管理员、2 个普通用户。
- [x] 建立统一响应、当前接口参数校验、错误处理中间件及可定位异常的服务端日志；后续模块继续添加各自参数校验。
- [x] 验收：从空数据库按 README 初始化并启动，装备查询可返回真实数据库内容；错误不会把数据库凭据返回给前端。

### 阶段二：认证与权限

- [x] 完成注册、用户名/邮箱登录、退出及当前用户接口；bcrypt 加盐轮次为 10，注册不能指定管理员角色，用户与空购物车在同一事务创建。
- [x] 实现登录页、注册页、受保护账号页、Pinia 登录状态、Token 持久化、启动恢复和路由守卫；浏览器实际操作仍待验收。
- [x] 实现 Axios 401 登录跳转、403 无权限提示、冻结提示、恢复失败重试及退出清理；登录失败 401 保留在登录表单。
- [x] 服务端校验身份、数据库当前角色和账号状态；冻结账号不能登录，已有 Token 的后续受保护请求也被拒绝；以 `/api/admin/me` 核验管理角色，无完整管理页。
- [x] 后端与真实 MySQL 验证：用户名/邮箱登录、重复注册、错误密码、无效/过期 Token、注册事务、冻结与角色权限；详见阶段记录。
- [x] 前端认证回归与生产构建：验证刷新去重、网络重试、退出、冻结/过期、跨标签状态、存储故障与安全回跳；不等同于浏览器点击验收。
- [ ] 浏览器验收：注册/登录、错误字段、站内跳回、刷新恢复、退出、跨标签同步、403 与网络失败后的重试逐项点击验证；不得用构建通过替代。

### 阶段三：装备浏览

- [ ] 列表展示图片、名称、价格、稀有度和库存；SSR 传说为金色、SR 史诗为紫色、R 稀有为蓝色、N 普通为白色，白色标签保持可辨识。
- [ ] 完成名称模糊搜索及防抖、稀有度多选、分类筛选、价格升降序、稀有度排序和每页 8/12/16 条分页。
- [ ] 完成装备详情，按类型突出攻击、防御或用途说明，不展示无意义的零属性；数量最少为 1，最多为当前库存与应用数量上限中的较小值。
- [ ] 列表提供加入购物车入口；售罄卡片显示“暂时售罄”并保留详情入口，仅禁用加购与购买，详情页库存不足时禁止继续加量。
- [ ] 验收：筛选组合后的总数和页码正确；空结果、图片失败、无此装备、售罄与低库存均有明确显示。

### 阶段四：购物车

- [ ] 游客购物车存于 localStorage；已存在的装备累加数量，支持修改、单项删除、批量删除和清空。
- [ ] 登录购物车由服务器持久化；更新数量以当前库存和应用数量限制为限，实时展示总价、0 优惠和应付。
- [ ] 登录后将本地和服务器同装备数量相加；成功确认合并后才清理本地数据，失败保留本地购物车并提示；结果不明时记录待核对状态，刷新也不自动重复累加。
- [ ] 对下架、删除和库存变化的购物车项给出明确处理结果；切换账号时不能出现上一用户的服务器购物车。
- [ ] 整车结算进入订单确认页；空车不能结算，失效项目未处理时不能静默漏单。
- [ ] 验收：匿名刷新、登录合并、同装备累加、库存边界、批删、清空和合并失败恢复均可复现。

### 阶段五：订单

- [ ] 确认页收集角色名、服务器和可选备注；角色名 2–10 字、服务器必填，前后端都校验。
- [ ] 提交前展示整车摘要；服务端重新读取装备状态与价格，拒绝订单请求中的重复装备 ID 并校验正整数数量；与当前整车及确认单价不一致时返回 409，不接受客户端定价。
- [ ] 创建订单使用数据库事务：校验 → 条件扣库存 → 创建待支付订单及快照 → 清空购物车；任一步失败全部回滚。
- [ ] 模拟支付只允许本人 `pending → paid`，记录支付时间；用户或管理员取消仅限 `pending`，状态更新与返库在同一事务内。
- [ ] 实现订单结果页、我的订单、订单详情；包含订单号、明细快照、角色信息、总价、优惠、订单金额和时间，按付款状态显示应付或实付。
- [ ] 用户订单支持状态及时间筛选、分页；所有查询和操作都校验资源归属，刷新详情页仍可工作。
- [ ] 验收：完整下单支付、待支付取消、重复操作、订单越权、多商品失败回滚、库存竞争和快照稳定性通过关键测试。

### 阶段六：管理端

- [ ] 装备管理：分页、搜索筛选、新增、编辑、上下架及软删除；名称、价格、稀有度、分类、图片、属性、描述和库存均可维护。
- [ ] 删除前检查关联 `pending`/`paid` 订单，有未完成订单则拒绝；历史订单仍保留快照。
- [ ] 库存通过独立增减接口调整，保证库存不为负；编辑其他商品字段不会把旧库存值写回。
- [ ] 用户管理：用户名/邮箱搜索、分页、冻结/解冻、用户基本信息及历史订单；不展示密码散列。
- [ ] 订单管理：全量订单按状态/时间/用户筛选，查看详情；允许 `pending → cancelled` 和 `paid → completed`。
- [ ] 验收：管理员完成一次装备维护、库存调整、用户冻结解冻及订单处理；普通用户直接请求管理接口仍被拒绝。

## 4. 必做测试清单

下列条目是完整项目的验收清单，并非全数通过。基础和认证部分的实际结果在阶段记录中单列；装备、购物车、订单及管理功能继续随实现执行。测试文档记录输入、步骤、预期、实际、结果和证据，不能仅以截图或构建通过替代业务验证。

| 编号 | 场景与预期 |
| --- | --- |
| T01 | 重复用户名/邮箱注册被拒绝；数据库密码不是明文；用户名和邮箱均能登录。 |
| T02 | 无效/过期 Token 返回 401 并触发登录跳转；普通用户管理请求返回 403。 |
| T03 | 不存在资源返回 404；字段错误返回 422 并指出字段；库存冲突返回 409 并说明可用数量；异常返回 500 且服务端留日志。 |
| T04 | 搜索、多个稀有度、分类、两种排序和 8/12/16 分页组合使用时，结果及总数一致。 |
| T05 | 售罄卡片仍可进入详情，但不能加购或购买；数量 0、负数、小数、超过库存不能加入或提交；正常边界数量可操作。 |
| T06 | 游客刷新不丢购物车；本地 2 件与服务器 3 件合并为 5 件；不足库存时明确提示；合并失败不删本地数据。 |
| T07 | 单删、批删、清空正确；切换账户后看不到上一账户购物车；总价和应付按整数分准确计算，未付款时不标为实付。 |
| T08 | 角色名 1/11 字或空服务器被双端拒绝；可选备注为空仍能下单；篡改确认单价、确认后商品变价或购物车变化返回 409；订单重复 ID 返回 422。 |
| T09 | 多商品订单中一项缺货，订单、明细、其他装备库存及购物车全部保持提交前状态。 |
| T10 | 两个用户竞争最后一件装备，最多一个下单成功，库存不为负；无需实现乐观锁系统。 |
| T11 | 待支付取消返库一次，重复取消不再次返库；重复支付不重复改变订单；支付与取消竞争仅一个状态变化成功。 |
| T12 | 用户不能查看、支付或取消别人的订单；已支付/完成订单不能走基础取消接口。 |
| T13 | 商品改名、改图、改价后历史订单快照不变；存在未完成订单时软删除被拒绝。 |
| T14 | 库存减少不能减到负数；下单扣库存后提交旧的商品编辑表单，不会覆盖最新库存。 |
| T15 | 冻结账户不能登录；冻结前已登录账户不能下单；解冻后可恢复正常操作。 |
| T16 | 用户与管理订单的状态/时间筛选、分页、详情正确；管理用户搜索及其历史订单可用。 |
| T17 | 空数据库初始化后，一名新用户能走完整购买流程；管理员能查看并完成该订单。 |

测试形式：页面功能按清单手动验收；事务回滚、并发库存、状态竞争、越权和金额计算优先用可重复的接口/集成测试验证，不用实现细节的镜像测试凑数量。

## 5. 种子数据与演示路线

- 16 件装备覆盖 SSR/SR/R/N 四档和至少四种分类，包含 0 库存、1 库存、低库存、普通库存及不同价格，便于演示排序和分页。
- 提供开发演示账户说明；演示用固定账户与真实环境凭据区分。历史订单测试数据通过正常业务或明确标注的测试夹具生成。
- 录屏顺序：启动说明 → 游客搜索筛选分页 → 查看详情并加入本地购物车 → 注册/登录并合并 → 修改与删除 → 整车确认 → 创建订单并支付 → 查看历史详情。
- 接着演示：另一待支付订单取消并观察返库 → 管理员维护装备和调整库存 → 冻结/解冻用户 → 查询订单并标记完成。
- 最后展示：库存不足、权限拒绝、字段校验中的代表性失败场景；带语音说明预期结果，避免只展示成功页面。
