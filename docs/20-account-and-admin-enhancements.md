# 角色与管理功能补全

2026-09-18，按已确认的三个小模块依次实现；不改动购物车、订单库存及模拟支付的既有规则。

## 1. 管理员配置游戏角色，用户只读查询

- 管理端用户详情提供选服、分配角色、修改角色名；仅适用于普通账号，不修改账号权限。
- “我的账号”新增各服角色及刷新入口。结算页依旧从数据库按当前身份和服务器取角色，无角色时提示联系管理员，不能自行填写或下单。
- 复用 `game_characters`，无需新增表或迁移。用户名与游戏角色名相互独立；同账号同服唯一，不提供删除、转移或变更所属服务器。
- 保存先锁用户行，再锁对应角色行。请求带读取时的 `expected_name`：首次分配为 null，修改为原名称。当前状态不符返回 409，防止旧页面覆盖新修改；当前名称已经等于目标时直接成功，重复请求不创建重复角色。
- 角色名称去两端空白后为 2–10 个 Unicode 字符，拒绝控制字符及未知字段。修改保留角色 ID，历史订单名称继续使用快照。
- 页面切换账号、用户或卸载时隔离迟到响应；保存结果未知（断网/5xx）及 404/409 后必须重新读取，成功核对后才能再保存。

## 2. 订单详情刷新与进度

- 用户订单详情常驻“刷新进度”，读取服务器最新详情，不触发支付、取消或重新创建订单。加载/操作中禁止重复刷新。
- 正常进度显示“待支付 → 待交付 → 已完成”；取消订单单独展示“订单创建 → 已取消”。状态和金额仍来自服务端。
- 复用 orders Store 的会话隔离、错误恢复和归属验证；没有新增轮询、超时自动取消或推送。

## 3. 管理概览与低库存

- `/admin` 和管理员无回跳地址登录默认进入 `/admin/overview`；原合法深链接仍优先。
- 概览读取同一只读一致性快照：待支付数、已支付待交付数、已支付及已完成订单的 `actual_total` 合计、在售且库存不超过 5 的装备数。金额单位为分，明确标注模拟支付。
- 订单卡片跳转状态筛选；低库存卡片跳转 `status=on_sale&low_stock=1`，包含 0 库存，不含下架和已删除。列表允许与其他条件组合，筛选状态可刷新恢复，重置时清除。
- `low_stock` 仅供管理接口使用，合法值为 `0`、`1`，公开装备接口不接受此参数。

## API

全部复用 `{code,message,data}` 响应，受保护数据禁止缓存。

| 方法与路径 | 权限与数据 |
| --- | --- |
| `GET /api/auth/me/characters` | 当前有效普通用户；仅读取认证身份自己的角色 |
| `GET /api/admin/users/:id/characters` | 有效管理员；目标须为普通账号 |
| `PUT /api/admin/users/:id/characters/:server` | 有效管理员；请求 `{character_name, expected_name}`，成功返回最新角色列表 |
| `GET /api/admin/overview` | 有效管理员；返回 `pending_orders`、`awaiting_delivery_orders`、`paid_amount`、`low_stock_count`、`low_stock_threshold`、`updated_at` |
| `GET /api/admin/equipments?low_stock=1` | 已有装备列表增加库存 ≤ 5 过滤，分页和总数使用相同条件 |

三个角色接口成功数据均为 `{items,servers}`；items 包含 `id,server,character_name,created_at`，servers 为 `{value,label}` 配置。目标账号不存在返回 404、目标是管理员返回 403、字段校验失败返回 422、角色状态冲突返回 409。
