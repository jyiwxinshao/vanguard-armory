# Vanguard Armory / 先锋军械库 UI Design System

本文件是游戏装备商城前台 UI 的统一设计规范。DeepSeek、Codex 或人工修改前端时，应优先遵守本文件；除非明确要求，不要自行创建新的视觉语言、品牌名、货币体系或交互模式。

## 1. 品牌与视觉方向

项目品牌统一为：

- 英文：**VANGUARD ARMORY**
- 中文：**先锋军械库**
- 页面功能标题使用中文，例如「装备商城」「我的订单」「购物车」。

整体风格为 **Industrial Tactical Minimalism（工业战术极简）**：

- 深蓝黑 / 黑曜石背景，低反射、克制、偏 PC 游戏客户端与战术终端视觉。
- 具有明显的“游戏装备商城”氛围，但不要模仿任何具体游戏 IP。
- 避免普通淘宝电商风、企业后台风、二次元手游风和高饱和霓虹赛博朋克风。
- 使用细边框、轻微层级亮度差和少量稀有度色彩建立层次，不依赖大面积渐变和强烈发光。
- 页面信息密度可以高于普通电商，但必须保持清晰、可扫描。

## 2. 核心配色

### 2.1 页面与容器

- 页面背景：`#0B0E14`
- 一级面板 / 顶部导航：`#121722`
- 装备卡片 / 交互容器：`#1A2130`
- 弹窗 / 更高层容器：`#1E2638`
- 常规细边框：`#252F44`
- 聚焦或选中边框：`rgba(56, 189, 248, 0.25)`

视觉层级主要依靠不同深度的深色背景 + 1px 细边框，不要大量使用阴影。

### 2.2 文字

- 主要文字：`#F1F5F9`
- 次要文字：`#94A3B8`
- 弱化文字：`#64748B`
- 不要使用纯白作为大面积正文颜色。

### 2.3 功能色

- 主交互青色：`#38BDF8`
- 成功 / 有库存：`#10B981`
- 危险 / 售罄 / 禁用警示：`#EF4444`

主操作按钮在所有可购买装备上统一使用青色体系，不因装备稀有度降低而变灰。只有真正不可用、售罄或禁用状态才使用灰化按钮。

## 3. 稀有度系统

稀有度颜色是前台最重要的识别元素之一，但只用于强调，不做大面积染色。

- **SSR / 传说**：`#F59E0B`
- **SR / 史诗**：`#A855F7`
- **R / 稀有**：`#38BDF8`
- **N / 普通**：`#94A3B8`

应用位置：

- 卡片 1px 边框或局部边框
- 稀有度标签
- 价格的轻度强调
- 装备图片区域底部约 4%–8% 的透明色调
- Hover 时的边框强化

禁止：

- 整张卡片使用高饱和纯色背景
- 大面积霓虹光晕
- 因 N 品质而把正常可购买按钮设计成禁用态

## 4. 字体与文字层级

推荐字体：

- 标题 / 装备名称 / 价格：`Space Grotesk`
- 中文正文、按钮、表单和常规 UI：优先系统中文无衬线字体，可与 `Inter` 混排
- 数字、少量属性数据：`JetBrains Mono`

中文界面可使用系统字体回退：

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", sans-serif;
```

建议层级：

- 页面主标题：28–32px / 600–700
- 区块标题：20px / 600
- 装备名称：16–18px / 600
- 正文：14px / 400
- 标签 / 属性：11–13px / 500
- 价格：18–20px / 700

## 5. 首页布局

### 5.1 顶部导航

首页顶部保持简洁，不重新堆叠交易终端信息。

左侧：

- Vanguard Armory / 先锋军械库 Logo 与品牌名

中部一级导航仅保留：

- 商城
- 我的订单

右侧：

- 购物车图标，可显示商品数量角标
- 未登录时显示登录入口
- 已登录时显示用户头像 / 用户名菜单
- 管理员可在用户菜单中增加「管理后台」入口

不要在顶部添加：账户资产、游戏币、服务器状态、交易量、市场行情、拍卖、Vault 等未实现功能。

### 5.2 标题区

主标题：**装备商城**

副标题建议：

> 探索稀有武器、护甲与战术装备，打造你的专属配置

保持简短，不描述项目实际不存在的交易协议或市场能力。

### 5.3 搜索与筛选

筛选区最多保持两行：

第一行：

- 搜索框：placeholder 为「搜索装备名称或代号…」
- 分类：全部 / 武器 / 护甲 / 饰品 / 道具

第二行：

- 稀有度：SSR / SR / R / N
- 仅显示有库存
- 排序：默认 / 价格升序 / 价格降序 / 稀有度

使用深色面板和细边框，不增加 Active Constraints、Parsing Index、实时行情等无业务价值的信息。

### 5.4 装备网格

桌面端固定以 **4 列**为主要视觉目标。

- 大屏：4 列
- 中等桌面 / 平板横屏：3 列
- 小屏：2 列
- 极窄屏：1 列（按实际开发需要）

卡片间距保持紧凑但不拥挤，推荐 12–16px。

## 6. 装备卡片

### 6.1 卡片结构

每张卡片只显示与列表浏览真正相关的信息：

1. 稀有度标签
2. 装备分类
3. 装备图片
4. 装备名称
5. 1–2 个核心属性
6. 库存状态
7. 人民币价格
8. 购买 / 查看详情操作

不要显示：

- 成色 / 磨损度 / Float 值
- 游戏币与人民币双重价格
- 美元市场换算
- 序列号、交易 ID、实时市场编号
- 实际项目不存在的资产交易状态

### 6.2 卡片容器

- 背景：`#1A2130`
- 边框：`1px solid #252F44`
- 圆角：`4px`
- 高稀有度卡片可使用对应稀有度细边框或极轻背景 tint
- 不要使用厚重投影

### 6.3 装备图片区域

- 建议 4:3 或接近 4:3
- 使用深色战术背景衬托装备主体
- 图片应成为卡片第一视觉焦点
- 可使用非常弱的内部径向渐变增强装备轮廓：

```css
radial-gradient(circle at 50% 40%, rgba(37, 47, 68, 0.4) 0%, rgba(11, 14, 20, 0.95) 100%)
```

### 6.4 属性

列表页最多显示 1–2 个核心属性，例如：

- 攻击 / 防御
- 伤害 / 射速
- 护甲 / 减伤

实际字段必须以数据库和 API 已实现的数据为准。不要为了视觉稿编造前端无法获得的属性。

完整属性放在装备详情页。

### 6.5 库存

正常：

> 库存：12 件

低库存：

> 仅剩 2 件

售罄：

> 已售罄

售罄状态：

- 卡片整体适度弱化
- 操作按钮禁用
- 使用危险或弱化色提示

### 6.6 价格

统一使用人民币，不使用虚构游戏货币或美元换算：

> ¥480.00

价格可以使用对应稀有度的轻度颜色强调，但首先必须保证可读性。

## 7. 按钮

### 主操作按钮

用于：

- 购买
- 加入购物车
- 确认
- 提交

规则：

- 主色：`#38BDF8`
- 深色文字或高对比文字
- 高度约 36px
- 圆角 4px
- Hover 可以轻微提高亮度或增强边框
- 不使用强烈外发光

### 次要按钮

- 透明 / 深色底
- `1px solid #252F44`
- Hover 时背景提升一个层级

### 禁用按钮

只在操作实际不可用时出现：

- 售罄
- 权限不足
- 表单状态不允许

## 8. 表单、搜索与 Element Plus

Element Plus 负责输入框、Select、Pagination、Dialog、Table 等基础交互，但必须覆盖默认浅色视觉，统一进入 Vanguard Armory 的深色体系。

### 输入框

- 背景：`#0E131D`
- 边框：`#252F44`
- 文字：`#F1F5F9`
- placeholder：`#64748B`
- Focus：`#38BDF8`
- 圆角：4px

### 下拉菜单

- 背景：`#121722`
- 边框：`#252F44`
- Hover：`#1A2130`
- 当前选项使用青色细边或文字强调

## 9. Hover 与动效

动效保持短、克制、功能导向。

装备卡片 Hover：

- 边框从普通边框过渡到稀有度色或青色
- 卡片亮度轻微提升
- 可进行 1–2px 的微小位移
- 不使用大幅缩放、旋转或强发光

建议：

```css
transition: border-color 160ms ease, background-color 160ms ease, transform 160ms ease;
```

## 10. 分页

沿用首页当前简洁分页视觉。

开发时分页总数必须使用后端返回的真实 `total`，不要固定展示大规模虚构数据。

示例：

> 共 16 件装备

页码数量根据真实分页结果计算。

## 11. Footer

Footer 保持低调，不承担业务功能。

可以显示：

- VANGUARD ARMORY / 先锋军械库
- Vanguard Protocol（仅作为世界观 / 品牌装饰）
- 课程项目说明或版权信息

禁止展示项目未实现的能力，例如：

- P2P 加密结算
- 第三方支付协议
- 实时市场交易协议
- 托管交易 / escrow
- 区块链或资产安全承诺

## 12. 后续页面一致性

装备详情、购物车、订单和登录注册页面必须继承本设计系统：

- 相同顶部导航
- 相同页面背景和容器层级
- 相同稀有度系统
- 相同按钮 / 输入框规则
- 相同字体和间距节奏

管理后台允许采用更标准的 Element Plus 后台结构，但仍使用同一深色配色、字体和品牌，不要切换成完全不同的蓝白管理系统。

## 13. AI 实现约束

给 DeepSeek / Codex 的前端任务默认附带以下约束：

1. 必须遵守 `docs/DESIGN.md`。
2. 不得重新设计品牌或整体风格。
3. 不得新增 Aurum、Credits、USD 换算、实时交易市场、Escrow、P2P 等未实现业务概念。
4. 不得引入新的 UI 框架；继续使用 Vue 3 + Element Plus。
5. 优先复用现有组件与 CSS 变量。
6. 不得为了视觉效果修改既有 API 契约。
7. 页面中的装备、库存、价格、分页等业务数据必须来自实际 API 或明确的开发 mock，不写死成视觉稿中的演示数据。
