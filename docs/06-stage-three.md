# 第三阶段：装备浏览

本阶段接入装备搜索、组合筛选、排序、分页与公开详情。用户已将首页改为 **VANGUARD ARMORY / 先锋军械库**，当前开发以用户现有代码为基础，保留四列装备卡片、两行筛选、导航和配色，并遵循 [DESIGN.md](DESIGN.md)。数据库结构和业务库中的账号、库存、装备数据无需重建。

上轮第三阶段验证中断。本轮已通过前端自动测试和生产构建，浏览器权限已恢复并完成部分实际操作；服务端、真实数据库和其余页面场景继续检查。以下记录只将已有结果的项目标为通过。

## 功能范围

- 按装备名称搜索，使用 300 毫秒防抖，中文输入法组合完成后再查询，回车立即提交；支持稀有度多选、分类、仅有库存和排序组合。
- “仅显示有库存”通过后端 in_stock=1 与其他条件共同过滤，结果和 total 均来自真实数据库；不再只过滤当前已加载的一页。
- 支持最新上架、价格升序、价格降序和稀有度排序，每页显示 8、12 或 16 件。
- 筛选变化回到第一页，清除筛选恢复默认条件，过页时调整到有效页；查询条件写入地址，刷新、浏览器前进后退和从详情返回可恢复查询。
- 列表与详情显示价格、品阶、类型、用途、非零属性和库存；售罄装备可查看，库存不超过 5 件时显示低库存提示。
- 详情区分加载、404 的不存在/下架、非法 ID 和连接/服务器失败；连接失败提供重试。快速切换条件或详情时，旧响应不覆盖当前结果，离开页面后不回写。
- 接通已有图片字段，暂用原有占位图；图片失败提供备用显示，正式装备美术留到后期。

当前卡片“查看详情”提供真实浏览入口；顶部“我的订单”、购物车按钮及数量角标是用户现有 UI 的业务预留，尚未接通订单与购物车。数量选择和加购将在第四阶段统一实现，本阶段不能购买或下单，不把预留按钮视为已完成业务。

保留用户当前视觉：页面 `#0B0E14`、面板 `#121722`、卡片 `#1A2130`、细边框 `#252F44`、主交互青色 `#38BDF8`；SSR/SR/R/N 使用 DESIGN 中的金、紫、青、灰四色。后续详情、购物车、订单和认证页面延续同一体系，不能以功能开发为由覆盖用户修改或恢复旧列表。图片暂用现有占位图，未生成或替换正式装备素材。

## 后端行为

`GET /api/equipments` 支持 keyword、rarities、category、in_stock、sort、page、page_size。关键词最多 50 个 Unicode 字符，只按名称匹配，并把 SQL 通配符当作文字；所有筛选值与排序方式由服务端校验。

in_stock=1 表示仅查询 stock > 0；0、空字符串或缺省表示不限制库存，其他值返回 422。库存条件与名称、稀有度、分类一起用于列表与 total，并与分页保持一致。

筛选后的总数与结果在同一只读事务快照中读取，排序用 id 处理同值次序。默认列表中库存为零的 on_sale 装备仍公开，启用仅有库存时只从列表筛除；详情始终允许查看合法的售罄装备。off_sale 和 deleted 在公共列表与详情中都不可访问。`GET /api/equipments/:id` 对非法 ID 返回 422，对不可访问的装备返回 404。详情返回地址只允许根目录及受支持查询，保留当前浏览条件。

完整参数规则见[数据库与接口设计](02-data-and-api.md)。
