# 第二阶段：认证与权限实现记录

2026 年 9 月 14 日补齐注册、登录、身份恢复、退出和基础权限校验。工程与数据库沿用[第一阶段成果](04-stage-one.md)；本文区分已实现功能、自动验证和仍未完成的浏览器验收。

## 已实现范围

| 部分 | 当前实现 |
| --- | --- |
| 注册 | 用户名、邮箱、密码校验；bcrypt 10 轮哈希；数据库唯一约束；普通用户与空购物车在同一事务创建 |
| 登录 | 用户名或邮箱加密码；签发 JWT；返回公开用户资料，不返回密码哈希 |
| 身份和权限 | `/api/auth/me` 查询当前用户；每个受保护请求读取数据库当前角色与冻结状态；`/api/admin/me` 仅允许管理员 |
| 退出 | 前端立即清除 Token 和用户状态，同时调用退出接口；不提供服务端 JWT 撤销名单 |
| 页面 | `/login`、`/register`、受保护的 `/account`、`/403`；导航加入登录/注册或用户名/退出 |
| 登录恢复 | Token 保存在 localStorage；启动有 Token 才调用 me；路由守卫等待验证，网络失败保留凭证并显示重试 |
| 错误处理 | 登录错误 401 原地提示；其他当前会话 401 跳登录；冻结 403 清身份并提示；普通 403 显示无权限 |
| 标签页与请求同步 | storage 事件同步身份；旧请求通过 Token 和身份版本校验，不能在退出或切换账号后恢复旧身份；同页仅最新登录请求生效，离开表单页后旧请求不会自行导航 |

现有装备目录视觉、文案、布局和配色保持原样，只新增认证所需的表单、导航和反馈。用户已明确 UI 后期自行调整，本阶段未开展页面重设计。

购物车操作及合并、订单、冻结管理页面和完整管理后台尚未实现。注册时创建空购物车记录只是数据库准备，不代表已提供购物车功能。装备图片、搜索、筛选、排序和详情仍待下一阶段。

## 当前接口

| 方法 | 路径 | 成功结果 |
| --- | --- | --- |
| POST | `/api/auth/register` | HTTP 201；返回新普通用户公开资料，不自动登录 |
| POST | `/api/auth/login` | HTTP 200；返回 token、expires_in（秒）和 user |
| GET | `/api/auth/me` | HTTP 200；返回当前有效用户资料 |
| POST | `/api/auth/logout` | HTTP 200；返回 `{ logged_out: true }` |
| GET | `/api/admin/me` | HTTP 200；返回管理员自身资料，普通用户请求为 403 |

所有成功结果保持 `{ code: 0, message: "success", data: ... }` 包装。公开用户包含 id、username、email、avatar、role、status、created_at、updated_at；完整字段与错误约定见[数据库与接口设计](02-data-and-api.md)。

## 账号和凭证规则

- 用户名去除两端空白后为 2–20 个 Unicode 字符，不能包含 `@` 或任何空白；邮箱去除两端空白并转小写，最多 50 个字符。
- 注册密码至少 8 个字符、UTF-8 编码最多 72 字节，不删除密码两端空白。确认密码只做前端校验，不发往注册接口。
- JWT 默认有效期 2 小时，使用 HS256、固定签发方及接收方校验；JWT_SECRET 必须配置为至少 32 字节的随机密钥，由本地配置生成脚本准备。
- 用户角色和冻结状态不信任浏览器或过期资料，每次受保护请求从数据库读取。冻结后已签发 Token 的后续请求也会被拒绝。
- 退出只清除本地身份，服务端不撤销已有 JWT；有效凭证仍受其到期时间、数据库用户状态和角色约束。
- 登录后的 returnTo 只允许安全站内路径，拒绝外站、`//`、反斜杠及登录/注册循环；页面和日志不展示完整 Token。
- 身份恢复遇到网络或 500 错误时不清 Token，也不显示为已验证登录；通过“重新验证”恢复，或由用户明确退出。
