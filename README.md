# 游戏装备商城系统

本项目按单人完成课程设计进行规划，目标是实现装备浏览、购物车、下单、模拟支付和后台管理的完整流程，并能够独立演示和说明实现原理。

当前前台品牌为 **VANGUARD ARMORY / 先锋军械库**。首页采用用户已修改的四列装备卡片、深色面板和青色交互体系；后续开发保留这些修改，并遵循 [UI 设计规范](docs/DESIGN.md)，不重新设计品牌或整体风格。

工程基础、认证、装备浏览、购物车和订单已接入。支持游客本地购物车、普通用户服务器购物车、登录自动合并、库存调整提示及安全重试；支持订单确认、创建、模拟支付、取消与订单历史。数据库为六张业务表，另含购物车合并与订单提交两张幂等回执表。完整后台继续按阶段开发，最新结果见[第五阶段记录](docs/08-stage-five.md)。

## 当前可运行内容

- 装备卡片读取真实 MySQL 数据，支持名称搜索、稀有度多选、分类、仅显示有库存、价格与稀有度排序，以及固定 12 条分页。
- “仅显示有库存”使用后端 `in_stock=1` 与其他条件共同过滤，分页条目和总数都来自同一查询条件，不只隐藏当前页的售罄卡片。
- 名称搜索使用 300 毫秒防抖，中文输入法组合完成后再提交，回车立即搜索；筛选变化回到第一页，超出有效页时调整页码。
- 筛选条件保存在地址中，支持刷新、前进后退和从详情返回；详情展示非零属性、用途、价格与库存，售罄装备仍可访问。详情区分不存在/下架与连接失败，后者提供重试。
- 数据库包含 22 件装备（其中 1 件售罄、6 件日蚀圣械新品）；包含管理员和两个普通用户，均已保存 bcrypt 哈希。
- `/api/health` 检查连接及关键表结构，`/api/meta` 返回游戏配置；`/api/equipments` 提供组合筛选与分页，`/api/equipments/:id` 查询公开详情。
- 支持用户名或邮箱登录；注册创建普通账号和空购物车记录，账号信息通过 `/api/auth/me` 查询。
- `/login`、`/register`、受保护的 `/account` 和 `/403` 已接入；`/admin` 已有独立布局与角色守卫，装备列表已接通真实查询、组合筛选和 10/20/50 条分页。默认展示在售及下架装备，已删除装备需主动筛选。其他管理页面仍为占位，详情及写接口返回 501；开发边界见[管理端骨架](docs/10-admin-scaffold.md)，本步结果见[装备列表记录](docs/11-admin-equipment-list.md)。
- Token 保存在浏览器 localStorage，刷新时向服务器确认身份；网络失败保留凭证并提供重新验证，退出同步到其他标签页。
- 保留用户当前卡片、筛选、导航和配色，后续页面复用同一设计体系。装备使用现有原创图片，失败后提供备用显示并避免循环加载。
- 详情页支持游客与普通用户加购；`/cart` 支持改数量、单删、原子批删、清空和真实数量角标。失效条目可删除，超库存条目可减至合法数量。
- 游客数据保存在 localStorage；普通用户登录后自动合并。同一批次重试不重复累加，明确成功后才清理本地批次，退出不复制服务器购物车。
- 勾选仅用于批量删除，摘要展示整车可购买金额；游客结算引导登录，登录用户进入订单确认页。
- 订单确认、创建、模拟支付、取消与订单列表/详情已接入；创建订单占用库存，取消返还库存，提交编号幂等避免重复下单。
- `/orders` 支持状态、日期筛选及分页，`/orders/:id` 显示快照、金额、时间并提供模拟支付和待支付取消。
- 创建订单在事务内扣库存、保存订单与快照、删除本次结算行；同一提交编号重试只生成一笔订单。响应丢失后可从“我的订单”恢复上次下单。

## 环境

Node.js 24 或更新版本、npm、MySQL 8.0.16 或更新版本。首次实现已在 Node.js 24.14.0、npm 11.9.0、MySQL 9.4.0 上运行通过。依赖在根目录统一安装，由 npm workspaces 管理 client 和 server。

## 首次启动

在本项目根目录运行：

```bash
npm install
npm run setup:env
```

打开 `server/.env`，填写本机 MySQL 的 `DB_USER` 和 `DB_PASSWORD`。默认数据库为 `game_store`，连接地址为 `127.0.0.1:3306`。密码如果含 `#`、空格等特殊字符，请使用引号包裹。`setup:env` 自动生成本地演示密码与 JWT 密钥；重复运行会保留现有文件。`JWT_SECRET` 必须是至少 32 字节的随机密钥，`JWT_EXPIRES_IN` 默认 `2h`。此文件已被 Git 忽略，不要提交真实密码。

```bash
npm run db:init
npm run db:seed
npm run db:check
npm run dev
```

已有旧数据库升级时，先执行：

```bash
npm run db:migrate
```

该命令会幂等地创建当前版本缺失的表、补齐已有表缺失的字段（当前为 `equipments.new_until` 与 `equipments.series_code`），通过完整结构校验后回填旧版日蚀圣械的空系列归属。回填同时匹配六件装备的原始名称与图片路径，仅修改为 NULL 或空字符串的 `series_code`；保留已有非空归属、库存、价格、状态、新品期限和时间戳，重跑不重复改动。已改名或换图的装备需在管理端上线后核对归属，不使用模糊匹配。

打开 [本地商城](http://127.0.0.1:5173/)。后端默认地址为 [本地 API 健康检查](http://127.0.0.1:3000/api/health)。开发服务仅监听本机，按 `Ctrl+C` 停止两个进程。

本机配置和数据库已完成后，平时只需运行：

```bash
npm run dev
```

前端将 `/api` 代理到后端，从 `server/.env` 读取非敏感的 HOST 和 PORT 配置。修改配置后重启开发服务。若端口被占用，先停止之前启动的开发服务；脚本不会擅自结束其他程序。

## 本次升级

已有项目执行一次 `npm run db:migrate`（或直接 `npm run db:init`），补建缺少的 `cart_merge_receipts`、`order_requests`，以及 `equipments.new_until`、`equipments.series_code`，保留原数据；本机已执行。全新安装使用 `db:init + db:seed` 即可还原当前 22 件正式演示装备。游客购物车使用浏览器 Web Locks 协调跨标签页写入，需要支持该能力的现代浏览器，并通过 localhost、127.0.0.1 或 HTTPS 访问。不支持或存储被禁用时会提示，不会假报保存成功。

## 初始化规则和演示账号

`db:init` 创建缺少的数据库与表，并执行幂等轻量迁移补齐已知字段；随后检查字段、关键类型、唯一键、外键和启用的 CHECK 约束，不删除数据，也不会自动迁移其他不兼容的旧表。MySQL 建表具有隐式提交，建表与种子写入不属于同一笔事务。

`db:seed` 仅在全部项目表都为空时，用一笔事务创建整套演示数据。任何一张表已有数据时整笔跳过，重跑不会重置库存、账号密码或冻结状态。初始化应在服务投入使用前完成。

| 用户名 | 用途 | 本地密码来源 |
| --- | --- | --- |
| admin | 管理员 | server/.env 中的 SEED_ADMIN_PASSWORD |
| player_one | 普通用户 | server/.env 中的 SEED_USER_PASSWORD |
| player_two | 第二个普通用户，后续验证订单归属与库存竞争 | server/.env 中的 SEED_USER_PASSWORD |

在[登录页](http://127.0.0.1:5173/login)使用演示账号，或在[注册页](http://127.0.0.1:5173/register)创建自己的普通账号。更改环境变量不会重置已经写入数据库的账号密码。

用户名为 2–20 个 Unicode 字符，不能包含空白或 `@`；邮箱最多 50 个字符；注册密码至少 8 个字符、UTF-8 编码最多 72 字节，密码两端空白不会被自动删除。注册成功后需登录。

退出会立即清除本地 Token 和账号状态，服务器不撤销已经签发的 JWT。有效凭证通常在 2 小时后过期；每次受保护请求还会查询数据库中的角色及状态，因此冻结账号后，已有 Token 的后续受保护请求也会被拒绝。当前没有冻结管理页面，该规则已通过接口和数据库测试验证。

## 验证

```bash
npm test
npm run test:db
npm run build
```

- `npm test`：运行 server 与 client 的自动测试，覆盖基础接口、输入校验、JWT、认证恢复，以及装备查询、库存筛选、购物车、订单、URL 恢复与旧响应隔离等逻辑；本轮结果见第五阶段记录。
- `npm run test:db`：运行真实 MySQL 基础、认证、装备、购物车及订单集成场景，包括注册事务、账号权限、组合库存筛选、真实总数、文字搜索、排序分页、详情可见性、下单扣库存、幂等回执、取消返库存和竞争处理。测试自行创建唯一命名的临时数据库，并在结束时删除该测试库；不会删除或改写 `game_store`。所用账号需要创建和删除临时数据库、创建触发器的权限。
- `npm run build`：检查并生成前端构建产物。当前仍以本地开发方式运行，尚未配置线上部署。

2026-09-16 用户端收尾已补齐固定 12 条分页、22 件带图片的演示装备、系列筛选和旧库升级回填。当前验证与管理端交接范围见[用户端收尾记录](docs/09-user-review.md#2026-09-16-用户端收尾)。

数据库连接失败时检查 MySQL 服务与本地配置；健康检查返回 `not_initialized` 时先建表，返回 `schema_mismatch` 时按初始化提示处理结构差异，不要通过删库来掩盖问题。

自动测试和构建不等于浏览器验收。第五阶段分别记录完整测试结果与页面验收；实际点击验证创建订单、模拟支付、刷新详情、状态筛选和取消。订单实现见[第五阶段记录](docs/08-stage-five.md)，最新用户端检查与修复见[用户端验收记录](docs/09-user-review.md)。
